# Release note draft

1. Read `changes.md` and `audience.md` before drafting.
2. Include only changes marked confirmed. Do not turn deployment timing or a freeze into release content.
3. Use the requested audience and keep each statement tied to a listed change.
4. This workflow does not decide whether a rollout should proceed.
